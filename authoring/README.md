# 教材の制作・改訂ガイド

この文書は、MOAW原稿を編集・表示・検査する担当者向けです。参加者の学習本文は[workshop.md](../workshops/agentic-copilot/workshop.md)、実習アプリや開催前の準備は[実習準備ガイド](../docs/design/workshop-preparation.md)に分けます。

## 1. 制作に使うSkillと表示方式

`moaw-workshop`は、[shinyay/moaw-copilot-kit](https://github.com/shinyay/moaw-copilot-kit)の次の固定版から、Skillディレクトリ全体を変更せず取り込んだものです。

- 参照版: `a1bad8fe077d768c7ab860ad5ddfd9a766064c57`
- 元の場所: `skills/moaw-workshop`
- 入口: [SKILL.md](moaw-workshop/SKILL.md)
- 再利用条件: [SkillのLICENSE](moaw-workshop/LICENSE)、[第三者著作物の表示](../THIRD-PARTY-NOTICES.md)

制作では、Skill本文、制作手順、MOAW形式、図解、描画上の注意、検査の参照に従います。
通常のCopilot設定へPluginをインストールする方式ではありません。ここへの配置だけでSkillが自動発見・有効化されたとは扱いません。
参加者が第4章で作る検証Skillとは別物であり、この制作用Skillを比較条件へ混ぜません。

受講者向けの本文へ、独立したローカルコピーでの補助試走、続く全39節の章順のCLI試走、Claude Opus 5.5による再試走、VS Codeによる2回の実機試走で見つけた改善を反映しています。実行結果は実習準備ガイドの第7節〜第11節で分けて管理し、配布用資産、人の受講者による通し確認、配布判定とは区別します。所要時間を推測で埋めず、ドラフト検査では`duration_minutes`の未設定を明示して許容します。公開用検査では許容しません。
キットのサイトや言語切替アダプターは複製せず、公式MOAWビューアのローカル表示を使います。

章別原稿はinclude用の断片です。画像の`assets/`は、結合後の`workshop.md`を基準に解決します。章別ファイル単体のMarkdownプレビューではなく、組み立てたMOAW表示で図を確認してください。

キットはコミュニティの制作支援です。著者・出典・ライセンスの表示は`THIRD-PARTY-NOTICES.md`と同梱資料で保持します。制作用ファイルを参加者の比較条件に混ぜません。

## 2. 本文へ書くこと、書かないこと

本編の各節は「この節のゴール → 解説 → 演習 → 結果を確かめる」を基本にし、必要なヒント・解説を近くに置きます。形式を埋めるだけでなく、実際の対象、操作、根拠、確認結果を具体的にします。

| 情報 | 置き場所 |
| --- | --- |
| 目的、概念、演習、依頼例、確認、ヒント・解説 | 共通MOAW本文 |
| 受講前に必要な環境、資産不足時に実操作を始めない判断 | 本文の「準備・記録・再開」 |
| 制作方針、レビュー観点、ビルド・表示・検査 | この制作ガイド |
| 未同梱の配布用資産、環境の確認、試走の記録、提供・配布の準備 | 実習準備ガイド |
| ACの正本、状態名、詳細設計、判断履歴・未決事項 | `docs\design`の各文書 |

本文には、章全体を「第1章」、各ページを「1-1」のように示します。「はじめに」と補足は番号なしとし、`SEC-xx`、S0〜S6、制作進捗の説明は設計・準備資料で扱います。
参加者が行う設計の「案」や、未実施・未確認の記録は必要です。制作メタ情報を除くために、仮説、例示、未検証、権限・安全条件まで削除しないでください。

## 3. ローカルで教材を表示する

次は教材制作用の手順であり、実習アプリの起動手順ではありません。Node.js 22以上とnpmを使い、リポジトリのルートで実行します。失敗した場合は次へ進まず、原因を確認してください。

```powershell
npm ci --ignore-scripts --no-audit --no-fund --cache .\.cache\npm
npm run build
node .\scripts\serve.mjs --port 4445
```

サーバーが表示した`http://127.0.0.1:.../workshop/workshop.md`を開きます。ポートが使用中なら`--port 0`で空いているポートを選べます。他のサーバーは止めません。
browser CANVASにも同じURLを渡します。別の端末ではその端末でサーバーを起動してください。loopback URLは公開サイトではありません。

サーバーは`Ctrl+C`で停止できます。バックグラウンド実行時のURLとNodeプロセスIDは、`.cache\preview.json`に記録されます。再起動後は新しいURLとIDを確認してください。
原稿を編集したら再度`npm run build`し、自分のサーバーを停止・再起動してからブラウザーを再読み込みします。新しい図やファイルは再起動時に配信対象へ反映されます。

組み立てには公式CLIの`moaw build`を使います。生成先は`dist\moaw`で、手で編集しません。
ローカル表示では生成物だけを配信し、Clarityタグを除いたHTMLシェル、外部自動要求を制限するCSP、変更していない公式JS/CSSを使用します。通常のCopilot設定や認証は変更しません。
作成者とフッターの表記は、このリポジトリの`scripts/viewer/workshop-presentation.js`とCSSで調整します。公式ビューア本体を書き換える方式ではありません。設定値は原稿のメタデータからビルド時に渡し、表示補助のファイルとハッシュを`build-info.json`へ記録します。ビューアの構造が変わって適用できなくなった場合は、画面とブラウザーのコンソールへエラーを表示します。
ここでいう教材のプレビューは、CopilotのPreview機能とは別です。

### 教材の表示名・作成者・版番号を変更する

表示に使う情報は、[workshop.md](../workshops/agentic-copilot/workshop.md)の先頭のYAMLにまとめます。

| 項目 | 用途 |
| --- | --- |
| `title` | 教材の正式タイトル |
| `short_title` | ヘッダーとブラウザーのタブに表示する短いタイトル |
| `footer_title` | フッターに表示する教材名 |
| `workshop_version` | 教材専用の版番号。`"1.0.0"`のように、`v`を付けない3つの整数で記載 |
| `authors`・`contacts` | 先頭の作成者のGitHubアカウント名とHTTPSプロフィールURL |
| `author_name` | 「はじめに」のアカウント名の下に表示する氏名 |
| `author_affiliation` | 氏名の下に表示する所属 |

今回の教材の版番号は`1.0.0`です。`package.json`の版番号やMOAWビューアのビルド番号とは別に管理します。フッターはOctocatアイコンに続けて`GitHub Copilot 活用ワークショップ (v1.0.0)`と表示し、MOAWへのリンクは置きません。元のライセンスと出典は[第三者著作物の表示](../THIRD-PARTY-NOTICES.md)と生成物の同梱ファイルに保持します。

表示名や版番号を変えるときも、このYAMLを編集し、ビルド・サーバー再起動・ブラウザー再読み込みを行います。生成済みHTMLや表示補助のJavaScriptに値を直接書き込まないでください。

## 4. 原稿と実表示を確認する

Windowsのブラウザー検査にはインストール済みMicrosoft Edgeを使います。一時データも作業コピー内に置きます。

```powershell
New-Item -ItemType Directory -Path .\.cache\tmp -Force | Out-Null
$env:TEMP = Join-Path $PWD '.cache\tmp'
$env:TMP = $env:TEMP
npm run check
npm run build
npm test
npm run test:browser
```

`check`は正本AC、章・ページ、SVG、ローカル参照を確認します。所要時間が未確定の間は、`duration_minutes`未設定を未完事項として報告します。`npm run check:publish`では、この未設定をエラーにします。
コンテンツテストでは章・節番号、導入、ゴール・演習・確認の存在、制作状況が本文へ混入していないことを確認します。ただし、文字列検査だけで教え方や事実の正しさを証明したことにはしません。

公式ビューアで全ページ、目次、前後移動、再読み込み、コード例、折りたたみ、図、狭い画面を確認します。SVGは読み込めるだけでなく、文字の大きさ、はみ出し、線の重なりも見ます。
表示補助の検査では、作成者が重複しないこと、GitHubプロフィールへのリンク、ヘッダー・タブ・全ページのフッター、画面幅320pxと390pxでの表示を確かめます。公式JS/CSSが元の配布物と一致することも検査します。
日本語の文中で太字を使うときは、閉じる`**`の直前に全角の閉じ括弧を置かないでください。たとえば`**fixture（フィクスチャー）**と呼びます`は、公式ビューアでは太字にならず記号が残ります。`**fixture**（フィクスチャー）と呼びます`のように、括弧を太字の外へ出します。実表示のテキストに`**`が残っていないかも確かめます。
教材の本文や表に書くパスは、`tests/test_filtering.py`のように`/`で区切ります。PowerShellとBashのどちらでも同じ表記で使えるためです。区切り文字そのものを説明する箇所を除き、`\`は使いません。
制作コードや表示の確認は、参加者環境の機能確認、アプリの実行、研修の試走、利用量削減の実証とは別です。

## 5. 教材レビューの観点

主な読者は、開発経験はあるものの、GitHubやGitHub Copilotを使い始めたエンジニアです。必要な専門用語は残し、初めて必要になる本文で短い説明や具体例を添えます。基本説明を用語集や折りたたみだけに置かず、何のために、誰が何を行い、何を見て判断するかが分かる順序にしてください。
見出し・表・依頼例・記入欄・ヒント・図の文言も同じ読者に向けて整えます。表現を分かりやすくするために、演習内容、到達目標、条件、否定、安全上の制約を変えないでください。実行コード・コマンド・パス・識別子と、改訂できる自然言語の依頼例は分けて確認します。文章の改訂を、初学者による評価や新しいプロンプトの実行済み記録には読み替えません。

| 観点 | 確かめること |
| --- | --- |
| 学習の目的 | 学べることと、各節で残す成果・確認がつながる |
| シナリオ | 同じ変更要求を追い、本編と独立演習の切り替えが分かる |
| 説明 | 必要な概念を説明してから操作へ進み、制作方針を講義の本文に混ぜない |
| 演習 | 何を入力し、何を依頼・操作し、何で結果を確かめるかが具体的 |
| 自習 | 口頭補足なしでも、ヒントと解説で再開できる |
| 正しさ | AC、期待値、条件、役割、未確認の範囲を維持する |
| 記録 | 本編・独立演習・支援・実行・測定・第三者確認を混同しない |
| 読みやすさ | 説明不足や重複、表・図・ページの分け方を実表示で確かめる |

レビューの記入例:

```text
章・節：
読み手が迷うところ：
学習上の影響：
維持する条件：
変える説明・演習・確認・図：
実習資産を用意してから確かめること：
```

## 6. 設計と本文を一緒に更新する

業務条件を変更するときは[共通シナリオ](../docs/design/common-scenario.md)から関連SECとMOAW原稿へ反映します。`AC-xx`、`SEC-xx`、`Q-xxx`のIDを別の意味に使い回しません。
確認済み事項、提案、未決事項は[管理文書](../docs/design/decisions-and-open-questions.md)で区別し、変更理由、影響、残る確認を記録します。本文の改訂だけで、実行していないテストや測定を成功に書き換えません。

章別原稿と生成済みの表示を別々の正本にしないでください。重要な変更は本文・準備資料・設計・実表示を合わせて見直し、公開や配布は別の承認と確認を経て行います。
