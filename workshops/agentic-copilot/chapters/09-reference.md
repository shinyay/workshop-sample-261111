## 補足｜用語と参照先

本文で使う言葉を、必要なときに確認するための一覧です。最初からすべて覚える必要はありません。

### GitHubと作業の記録

| 用語 | この教材での意味 |
| --- | --- |
| Git／GitHub | Gitはファイルの変更履歴を管理する道具。GitHubはコードや履歴を共有し、開発を進めるためのサービス |
| リポジトリ／作業コピー | リポジトリはファイルと変更履歴の保管場所。作業コピーは自分が編集・実行するフォルダー |
| コミット／差分 | コミットは変更をGitの履歴に記録したもの。差分は、比較する二つの状態の変更内容 |
| HEAD | 今の作業コピーが基にしているコミット。`git rev-parse HEAD`でコミットIDを表示できる |
| 対象版 | 今回のコードの状態。コミットIDだけでなく、まだコミットしていない変更や新規ファイルも含めて識別する |
| 開始版／参照版 | 開始版は、配布される絞り込み実装前の実習アプリで、本編はここから始める。参照版は、教材の説明の基にした固定版（コミット`1a411cd`） |
| 講師用の完成例／演習版 | 講師用の完成例は、講師が確認用に用意した実装例で、自分の実装の合否基準にはしない。演習版は、自分たちが絞り込みを実装していく本編の版 |
| 原記録 | 実行時の出力やテスト結果のファイルなど、要約の基になった記録。要約と一緒に、確認できる場所を残す |
| ブランチ | 他の作業と分けて変更履歴を進めるための分岐 |
| PR（Pull Request） | 変更内容を共有し、レビューや取り込みを依頼するもの |
| 本編 | 同じアプリを引き継ぎ、絞り込みを計画・実装・確認する継続した作業 |
| 独立演習 | 条件の比較や不具合の判断を学ぶため、本編とはコード・データ・会話を分けて行う演習 |
| 正本 | 規則や条件を確認するときの基準として管理する文書。別の場所へ同じ規則を写す場合も、基準との一致を保つ |

### Copilotへ仕事を任せる

| 用語 | この教材での意味 |
| --- | --- |
| プロンプト | Copilotへ送る依頼文。目的、必要な情報、許可する操作などを伝える |
| モデル | Copilotが回答やコードを生成する際に使うAI。比較中は指定された一つを使う |
| コンテキスト | Copilotがその処理要求で扱う情報。依頼、指示、会話履歴、参照ファイル、ツールの結果など |
| ツール／実効ツール | ファイルの読取や検索、編集などを行う道具。実効ツールは、設定に書いたものではなく、その実行時に実際に使える道具 |
| 指示／Custom Instructions | 繰り返し守る規則を伝える仕組み。特定の作業だけに使う指示もある。操作を禁止する権限設定とは別 |
| AGENTS.md | AIエージェントに向けて、プロジェクトの規則や確認方法を書いておくファイル。第3章で扱う |
| コンテンツの除外 | 指定したファイルをCopilotの利用対象から外すための管理設定。対応する機能・環境は公式資料と管理者の案内で確認し、除外されたファイルを別の手段で読み直さない |
| Custom Agent | 役割、報告する内容、利用ツールなどをまとめた担当の設定。この教材ではレビュー担当を作る |
| Skill | 特定の仕事で使う知識、手順、資料などをまとめたもの。この教材では検証の手順を作る |
| front matter | Markdownファイルの先頭に書く設定部分。名前や説明などをYAML形式で記述する |
| トークン | AIが文章やコードを処理するときの単位。文字数や請求額と同じではない |
| キャッシュ | 対応する環境で、以前に処理した入力の一部を再利用する仕組み。過去の会話がすべて無料になる意味ではない |
| トークンエコノミー | 必要な品質を保ちながら、AI利用量と、調査・生成・確認・やり直しの負担を評価・改善する考え方 |

### 結果を確かめ、人が判断する

| 用語 | この教材での意味 |
| --- | --- |
| AC（受け入れ条件） | アプリが要求を満たしたか判断する条件。「はじめに」のAC-01〜AC-11を共通の基準にする |
| クエリパラメーター | URLの`?`以降で渡す`department=engineering`のような指定。`department`がキー、`engineering`が値 |
| リファクタリング／公開挙動 | リファクタリングは、外から見える動作を変えずにコードの構造を整理すること。公開挙動は、画面やAPIが受け付ける入力と返す結果 |
| 契約／期待値 | 契約は、仕様として守る入力の条件や結果の約束。期待値は、その条件とデータからあらかじめ決めた正しい結果 |
| 検証／回帰確認 | 検証は、対象が決めた条件を満たすか確かめること。回帰確認は、変更後も既存機能が壊れていないかの確認 |
| fixture | テストで使うデータや環境を準備する仕組み。使用するfixtureによって、初期データや期待する件数が変わる |
| アサーション | テストの中で、実際の結果が期待どおりかを確かめる文。Pythonの例では`assert`を使う |
| 反例 | ある説明や実装が正しくないと示せる具体例。正しい処理と誤った処理で結果が違う入力・データを考える |
| レビュー／採否 | レビューは、変更内容や確認結果を読み、問題や不足を調べること。採否は、指摘や変更を採用するかどうかの判断 |
| HITL／HOTL | HITLは定めた地点でAIが人の判断を待つ進め方。HOTLは合意範囲で作業を進め、人が状況を見て必要なら介入する進め方 |
| 観測／仮説／欠測 | 実際に見た事実、その原因についての考え、取得できなかった測定値。三つを混ぜて記録しない |
| A/B比較 | 一つの違いが結果にどう関わるかを、条件を揃えて比べる方法。この教材では品質も同じ基準で確かめる |

### アプリを動かす環境と自動処理

| 用語 | この教材での意味 |
| --- | --- |
| 配備（デプロイ） | アプリを実行先の環境へ配置し、動かせるようにすること。この教材では実環境への配備は行わない |
| Terraform | サーバーなどの構成や設定をコードで定義する道具。HCLという言語で定義を書く |
| CI／CD | CIはコードの変更を取り込み、ビルドやテストなどを行う継続的インテグレーション。CDは確認した成果物を配備へ進める仕組みで、この演習では定義案だけを作る |
| Azure Pipelines／パイプライン | Azure Pipelinesはビルド・テスト・配備などを自動化するサービス。パイプラインは、それらの処理の順序や条件を定めたもの |
| job／stage | jobは一まとまりの処理。stageは複数のjobをまとめる大きな区切り。環境や記録がそのまま引き継がれるとは限らない |
| 品質ゲート／JUnit | 品質ゲートは次の工程へ進んでよいかを判断する確認。JUnit形式はテスト結果をツール間で受け渡すための記録形式 |
| DR | 第7章で使う、配備環境や自動処理の要件の識別子。アプリの品質条件であるACとは区別する |
| 成果物／digest | 成果物は第7章で受け渡すZIPなどのファイル。digestはファイルの内容から計算する値で、内容が同じかを照合するために使う |
| state | Terraformが管理する資源の状態を記録した情報。この演習では実際のstateを操作しない |

### 困ったときに確認する順序

まず、今使っているコードの状態、作業フォルダー、データが演習の指定と合っているかを確認します。次に、Copilotへ渡す指示、実際に使えるツール、確認する手順を見直します。それでも判断できない場合は、入力した内容、返った結果、まだ分からないことをまとめて講師へ相談してください。自分の変更を残し、対象が分からないDBや他の人の作業を削除してやり直さないでください。

## 補足｜学習の振り返りと再開

自分が作成したメモ、指示、設定ファイル、コードの変更内容、確認結果、改善設計シートを見返してください。機能名を覚えたかではなく、何を任せ、その結果のどこを見て判断できるようになったかを振り返ります。

| 振り返ること | 自分の成果で説明すること |
| --- | --- |
| 調査と計画 | どの根拠から、何を、なぜ変えると決めたか |
| 指示の使い分け | 今回だけの要求と、継続的な規則をどう分けたか |
| AgentとSkill | 役割・手順・許可範囲をどう定義し、利用をどう確かめたか |
| 実装と確認 | 修正前後で同じ入力条件と期待結果を使い、失敗の理由と修正後の結果を説明できるか |
| レビューと人の判断 | どの指摘をなぜ採用・保留・見送りにしたか |
| 配備・自動化の定義 | 定義間の対応と、実環境で残る確認は何か |
| 改善の評価 | どの条件で何が分かり、次に何を一つ変えるか |

### 学習記録を残す

次の欄を自分のメモへ追記してください。自分で操作したこと、記録を読んで理解したこと、ヒントを使ったことを分けます。自分の読み直し、AIによる確認、他の人による確認も区別してください。

```text
自分で説明できるようになったこと／根拠となる成果：
実際に操作・実行・測定した範囲：
読解やヒントで学んだ範囲：
まだ確認していないこと：
次に戻る節と、その節で確かめること：
自分の仕事で最初に試す一つの変更：
```
