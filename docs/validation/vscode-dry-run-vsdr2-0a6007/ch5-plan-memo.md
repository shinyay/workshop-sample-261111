## 現状（資料・コードから分かったこと）

- 一覧画面 `GET /requests` と一覧API `GET /api/requests` は、同じ `read_requests`（`request_portal/__init__.py`）で検証と取得を行う。
- 開始版は `_validate_query_keys(set())` で、`scoutTheme` 以外の検索キーと重複キーを400で拒否する（83〜90行目）。
- 取得は `storage.list_requests`（条件なし、`created_at DESC, id DESC`）。全体集計は `storage.status_counts`（別のSQL、`GROUP BY status`）。
- `scoutTheme` は未指定・空文字・`light`・`dark` を受け付け、それ以外と重複は400。配色は画面のスクリプトがURLから読む（`base.html` 8行目）。
- 段階名は `WORKSHOP_STAGE = "starter"`。画面上部の案内と `/healthz` に出る。`tests/test_portal.py` 52〜67行目は `starter` と `reference` だけを想定する。
- `tests/test_reference_patch.py` は講師用の完成例パッチの確認で、現在のソースが `starter` であることを前提にする（73行目）。
