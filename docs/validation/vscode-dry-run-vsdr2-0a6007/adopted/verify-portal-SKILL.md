# 申請ポータルの検証

## 使うとき

申請ポータルの変更前後の動作、回帰、演習の受け入れ条件を確認する。検証に限定し、実装やテストの修正は行わない。

## 受け取る情報

- 対象版と期待する動作: 初期アプリ、完成例、または参加者の変更と、その確認したい要件。
- 作業場所: 対象のワークスペースのルート、ホストかDev Containerか、対象のリビジョンや未コミットの変更。
- 範囲: 変更箇所、確認したい機能、必要な自動テスト・静的確認・ブラウザー確認。
- データ: 対象DBの場所、架空データであること、現在の状態、既存データを変更してよいか。
- 実行環境: Python、uv、ロック済み依存の準備状況。ブラウザー確認を求められた場合はWindowsホスト、Edge、ブラウザー用依存、サーバーの状態と成果物の保存先も確認する。

指定されていない情報は、既存の正本や作業環境から確認できる範囲で確かめる。対象や安全性に必要な情報が不明なら、不足を明示して利用者に確認し、影響を受ける検証は保留する。指定されていない要件、コマンド、参照先を作らない。

## 対象とデータの確認

1. 対象ルートの AGENTS.md（`../../../AGENTS.md`） と README.md（`../../../README.md`） の該当箇所を読み、適用される指示、対象機能、対応するテスト、受け入れ条件を確認する。参加者の作業中は講師用の完成例パッチを読まず、適用もしない。
2. 指定された作業場所・リビジョン・未コミットの変更を確認し、別のコピーや稼働中サーバーを対象と取り違えない。画面上部や `/healthz` の表示は版の確認に使えるが、それだけでサーバーが指定の作業場所のコードを実行していると判断しない。不一致や確認不能な点は報告する。
3. 初期アプリでは絞り込み未実装と未対応条件への400応答が正しい。完成例や参加者の変更では、依頼された要件と正本の受け入れ条件に照らして確認する。表示上の `starter` だけで参加者の変更内容や期待動作を決めつけない。
4. 使用するデータが架空であること、DBの場所と現在の状態を確認する。不明なDBや実データの可能性があるデータを操作しない。初期化、リセット、パッチ適用、既存の変更の破棄は検証のために行わず、必要なら担当者または利用者に準備を依頼する。

## 確認方法の選択と実行

1. 対象ルートの正本に記載された方法から、変更に対応する確認を先に選び、必要に応じて全体の回帰テストと静的確認を選ぶ。正本と依頼が食い違う場合は勝手に期待値を決めず、差異を報告して確認する。
2. 自動確認のコマンドはこのSkillに写さない。実行前に AGENTS.md（`../../../AGENTS.md`） の「確認コマンド」を読み、そこに書かれたものから対象と範囲に合うものを選ぶ。講師用パッチのテストを外す理由と、全件を実行する場面も同じ節にある。

3. 対象ルートから、必要なPython、uv、ロック済み依存が準備済みで、実行時に依存の取得・追加・更新や設定変更が発生しないと確認できる場合に実行する。`uv run --locked` やオフライン指定だけでは依存の追加が起きないとは判断しない。不足や副作用が不明なら実行せず、準備を担当者または利用者に依頼する。コード・テストの修正、依存追加、設定変更はこのSkillでは行わない。
4. 自動テストは正本に従い一時ディレクトリの専用DBを使う。検証の対象や環境を確認できない場合は、実行済みの別の確認と区別して未実施とする。
5. 実ブラウザー確認は任意とし、依頼された場合に正本の方法を選ぶ。Windowsホスト、Edge、準備済みのブラウザー用依存、対象コードのサーバー、初期データ12件、保存先を確認する。この確認は専用デモDBに架空申請を2件追加し承認・差し戻しを行うため、対象DBへの変更と成果物の作成・既存ファイルへの影響について事前に利用者の許可を得る。条件や許可が不足する場合は実行しない。依存のインストールや環境設定は担当者または利用者に依頼する。
6. 各確認のコマンド、終了コード、結果、対象版、データへの影響と成果物を記録する。自分が起動したサーバーは確認後に停止し、既存のサーバーは無断で停止しない。

## 失敗の切り分け

失敗した確認、テスト名、期待値と実際の結果、関連するエラーを記録する。作業場所や版の取り違え、データ状態、環境・依存不足、アプリの動作、テストや正本との不一致を区別し、根拠が足りなければ原因は未確定とする。依存不足をアプリの不具合と決めつけない。

安全に確認できるログや対象箇所を読み、必要なら同じ正本の確認を同じ条件で再実行する。データ変更を伴う確認は再実行の影響と許可を改めて確認する。問題を修正したり、新しいコマンドや手順を作ったりせず、再現情報とともに実装担当者または利用者に戻す。

## 報告

- 対象の作業場所、リビジョンまたは変更、版、対象機能と期待した要件。
- データと実行環境の確認結果、参照した正本、選んだ確認方法とその範囲。
- 実行したコマンド、終了コード、成功・失敗、確認できた結果と必要な成果物の場所。
- 失敗の再現情報、期待値と実際の結果、根拠付きの切り分けまたは原因未確定、戻し先。
- 未実施の確認と理由、不足している入力・必要な準備や許可、データ変更などの実際の影響。

実行していない確認を成功と扱わない。報告やログには個人情報や秘密情報を含めない。
