## 1. 状態の定義

| 状態 | 意味 |
| --- | --- |
| CONFIRMED | ユーザーが明示した管理方針・制約、または出典を確認できた事実 |
| PROPOSED | 現時点の設計案。理由があるが、最終的な採用を確定していない |
| OPEN | 後続の教材化・実施条件を決めるために、判断や確認が必要 |
| SUPERSEDED | 別の判断で置き換えた事項。元の理由と置換先を保持する |

AIが作成した文書を保存・コミットしたことは、内容全体への最終承認ではない。
OPENは設計を進めるために可視化した論点であり、現在の設計文書作成の作業範囲が不明という意味ではない。

### Q-016: SEC-06の判断事例、関与方針、学習評価の成立性

## 5. 判断を更新する手順

1. 関係するQ-IDと、提案している変更を特定する。
2. 選択肢、採用理由、根拠、影響する文書とACを整理する。
3. 実際に決めた人または明示的な承認の根拠を記録する。
4. 共通シナリオと関連文書を同じ変更で更新する。
5. 元の判断を削除せず、置き換えられた場合はSUPERSEDEDと置換先を残す。

時間や費用の仮説は、根拠を得た範囲で更新する。
製品の機能説明は、対応する環境と参照元を記載する。
