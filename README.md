# GitHub Copilot 活用ワークショップ

一つの業務アプリの改修を通して、エージェントへの任せ方、共通指示、役割、再利用する手順、品質確認、トークンエコノミーを学びます。
目標は、機能を一通り操作することではなく、**必要な情報を渡して作業を任せ、品質と利用量を根拠に進め方を評価できること**です。

参加者用の実習アプリ、実行用のCustom Agents・Skills、欠陥入り教材、比較用コピー、Terraform・Azure Pipelines定義は含みません。本文の解説・演習・確認と、実行用資産の準備は別工程です。
このリポジトリをcloneしても、まだ実習アプリは起動できません。Template repository設定も有効にしていません。

原本を変更せず、独立したローカルGitリポジトリで、導入・本編39節・補足を章順にCLIで試走しました。章間の引き継ぎ、失敗と訂正、改善設計シートの作成、別会話のAI読み手による再確認までを[今回の記録](docs/design/workshop-preparation.md#8-copilot-cliによる章順の試走)にまとめています。[前回の主要演習の補助試走](docs/design/workshop-preparation.md#7-ローカル補助試走の記録)とは別の記録です。
その後、受講者役・判断者役のモデルをClaude Opus 5.5に変えて同じ条件で再試走し、見つけた改善を本文へ反映しました。結果は[再試走の記録](docs/design/workshop-preparation.md#9-claude-opus-55による再試走)に分けています。再試走後の見直しで、欠落していた本文3か所の訂正、値の照合の決定（D-045）、用語・表記の統一を行い、2026-10-26時点の教材をベースライン（タグ`workshop-baseline-2026-10-26`）としました。

教材の基本環境はVS Codeのままです。今回のCLI試走を、VS Code／Codespacesの操作確認、人による第三者評価、実クラウドの確認とは扱いません。比較の失敗や未確認も残しており、全条件が成功したという意味ではありません。

## 教材の構成

**「はじめに」＋本編8章・39節＋補足の47ページ、10点の図**で構成します。本編の各節は、ゴール、解説、演習、結果の確認、ヒント・解説を通して学ぶ形です。制作方針や準備の進捗は、上記の担当者向け資料に分けています。

本編は8章で構成し、各ページを節として「1-1」「1-2」「2-1」のような章番号-節番号で表記します。節番号は各章で1から始め、見出し・目次・前後のページへの移動に共通で使います。
章全体への参照や図では「第1章」〜「第8章」を使い、「はじめに」と補足には節番号を付けません。設計文書の`SEC-01`〜`SEC-08`は追跡用のIDとして残し、MOAWのページIDと原稿ファイル名も維持します。

「はじめに」の6ページで、目的、学べること、共通課題、学習の流れ、受講前の確認（教材と実習コードの入手先を含む）、ACを押さえます。ヒント・解説・解答例は同じ教材内で必要時に開き、自習も自己確認で進められます。折りたたみは閲覧上の支援であり、アクセス制御ではありません。

図・ヒント・ページ移動は公式MOAW表示で確認できます。ローカル表示の手順は[制作ガイド](authoring/README.md)、出典とライセンスは[第三者著作物の表示](THIRD-PARTY-NOTICES.md)を参照してください。教材が表示できることと、実習アプリが実行できることは別です。

## 共通シナリオ

題材は、架空の社内申請ポータルです。担当部署と申請状態による絞り込みを追加し、画面とAPIの整合、既存機能、入力検証を維持します。
要件整理から運用への引き継ぎまで、同じ変更要求でつなぎます。
全体は「理解と計画（第1章・第2章）」「任せ方の準備（第3章・第4章）」「実装と品質判断（第5章・第6章）」「引き継ぎと改善（第7章・第8章）」の四つのまとまりです。章の増減ではなく、今の目的と次へ渡す成果を見やすくする整理です。

| 章・節 | 学ぶこと | 次へ渡すもの |
| --- | --- | --- |
| 第1章: 1-1〜1-3 | Copilotの仕事の進み方と、文脈・利用量の捉え方 | 観察メモと調べたい問い |
| 第2章: 2-1〜2-5 | 現状理解、改善候補、要件、変更と確認の計画 | 根拠付きの調査・実装計画 |
| 第3章: 3-1〜3-5 | 共通・条件付き指示の作成とA/B/C比較 | 採用した指示と比較記録 |
| 第4章: 4-1〜4-5 | レビューAgent、検証Skill、個別比較、引き継ぎ | 定義と適用・利用の記録 |
| 第5章: 5-1〜5-5 | テスト先行、小さな実装、デバッグ、画面と回帰の確認 | 実装候補と同じ版の確認結果 |
| 第6章: 6-1〜6-5 | 指摘の採否、追加確認、HITL／HOTL、本編の品質判断 | 品質根拠と人の関与方針 |
| 第7章: 7-1〜7-5 | Terraform・Azure Pipelinesの作成、変更、横断レビュー | 定義と未設定・未検証の引き継ぎ |
| 第8章: 8-1〜8-6 | 参照指定だけを変えるA/B、採否、改善手順 | 改善設計シートと次に試すこと |

本編と独立演習のコード・DB・結果を混ぜず、各対象で得た根拠を使います。レビューAgentは読取・指摘まで、検証Skillは検証・切り分け・報告までとし、修正と人の判断を分けます。
実環境へのクラウド接続・適用・パイプライン実行は行いません。比較では品質を先にそろえ、削減率や特定条件の勝利を合格条件にしません。

業務条件は[SCN-01](docs/design/common-scenario.md)を正本とし、`AC-01`から`AC-11`で参照します。
AND条件、正常な0件とエラー、結果件数と全体集計の違いを、説明用のデータと確認方法まで含めて整理しています。
例示したデータは、実在の顧客データではありません。


製品の説明は各文書の公開ドキュメントを参照しています。必要な機能を非Previewで利用できること、権限、記録方法は参加者環境で別途確認します。
本文未確認の社内資料やWIPの抜粋を確定仕様として転記せず、WorkIQによる原本取得は行っていません。

参照元はPrivateです。本リポジトリへのアクセスだけで、参照元の閲覧権限が付与されるわけではありません。
